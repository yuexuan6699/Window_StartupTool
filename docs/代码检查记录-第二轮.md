## 三、本轮新发现问题（M5 新增代码）

### N1【中-严重】配置未拉到时编辑脚本，保存会清空心跳令牌并重置守护字段

- 位置：`App/ViewModels/MainViewModel.cs:229-232`（兜底构造）＋ `Core/Ipc/IpcServer.cs:344-376`（HandleUpsertScript 整对象替换）＋ `App/ViewModels/ScriptEditViewModel.cs:185-193`（BuildConfig 只保留 _original 上的字段）
- 事实链：GetConfig 失败被静默吞掉（`AppClientService.cs:88-91`、`MainViewModel.cs:289-293`），此时 `_config` 是默认空配置；点编辑走兜底分支 `new ScriptConfig { Id=row.Id, Name=row.Name }`——HeartbeatToken=""、DependsOn 空、守护阈值默认；编辑窗 BuildConfig 在这份残缺对象上回填可编辑字段；服务端 upsert 对已存在 Id 做**整对象替换**（只保留 Order，`IpcServer.cs:364-365`）→ 用心跳的脚本令牌被清空（全部 --beat 随即返回 12）、依赖/阈值/重启计数配置被重置。
- 触发条件：服务端 GetConfig 异常、或连接刚建立配置尚未返回的瞬间点编辑（窗口窄，但界面没有任何「配置未就绪」禁用保护）。
- **状态：已修复（第三轮 2026-10-14），双端各一道**：
  1. 服务端 HandleUpsertScript 对已存在 Id 改**字段合并**：保留 Order、HeartbeatToken、DependsOn、RequireElevation、InitialDelaySeconds、WaitForNetwork（编辑窗未暴露/服务端权威字段），只接受可编辑字段新值；
  2. 客户端 EditAsync 删除残缺兜底分支：配置未命中时先强制 ReloadConfigAsync 一次，仍取不到则弹错误提示拒绝开窗（新增双语键 Str.Edit.ConfigUnavailable*）。
  3. 回归测试 `Upsert_更新脚本_令牌与未编辑字段保持不变_N1_N3`（模拟残缺对象 + 伪造令牌提交，断言令牌/依赖/提权/延迟/等网络/Order 全部保留、可编辑字段生效）。

### N2【中】UpdateSettings 无范围校验，可写入让熔断逻辑失常的值

- 位置：`IpcServer.cs:247-252`（`cfg.Settings = p.Settings`，null 已被 Normalize 兜底，但数值不校验）
- 事实：`CircuitWindowSeconds=0` 会被保存，`ScriptSupervisor.cs:420` 用 `TimeSpan.FromSeconds(0)` 作熔断窗口 → 任何启动都立即熔断；Language 接受任意字符串；负数/超大值无约束。管道授权给所有交互用户（见 M3），等于普通用户可让全工具守护停摆。
- **状态：已修复（第三轮 2026-10-14）**：新增 `GlobalSettings.Validate()` 服务端白名单（LogMaxSizeMb 1–1024、LogRetentionDays 1–3650、CircuitWindowSeconds 1–86400、CircuitMaxStarts 1–1000、Language ∈ {null, zh-CN, en, system}）；updateSettings 校验失败回 `invalidPayload` 且**不写配置**；SettingsPayload.Settings 为 null 同样拒绝。回归测试 `UpdateSettings_非法值_拒绝且旧值保留_N2` + `SettingsValidationTests` 14 例。
- 附带发现（未修，低）：`ConfigJson.Clone`/落盘使用 WhenWritingNull，GlobalSettings.Language=null（跟随系统）经一次 Mutate 往返后变为模型默认 "zh-CN"——非中文系统上"跟随系统"选择在保存/重启后实际落成中文。修需调整克隆/文件格式，待与用户确认后处理。

### N3【中】UpsertScript 接受客户端自带 HeartbeatToken（可伪造心跳身份）

- 位置：`IpcServer.cs:344-372`（直接保存反序列化的完整 ScriptConfig，未剔除/重置 HeartbeatToken）
- 事实：任何能连管道的交互用户都可新建一个 Id/令牌自选的脚本配置，随后用该令牌通过 --beat 让「该脚本」永远被判存活；虽不能直接操控他人脚本，但令牌应由服务端独占生成（H2 设计本意），客户端载荷里应忽略该字段。
- **状态：已修复（第三轮 2026-10-14）**：HandleUpsertScript 任何路径都不接受客户端令牌——新建脚本强制置空（由 getHeartbeatToken 首次访问时按需生成），更新脚本保留服务端现值。回归测试 `Upsert_新建脚本_自带令牌被忽略_N3`（伪造 64 字符令牌被清空、getHeartbeatToken 生成新值且不等于伪造值）。
