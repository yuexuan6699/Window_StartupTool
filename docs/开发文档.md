## 2. 关键设计决策

### 2.1 进程托管：Job Object + 每脚本状态机（A4/A5/A6）

- **Job**：每实例一个 Job，设 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`，**不授予** BREAKAWAY。脚本根进程及其所有子孙（含 `start`/cmd 派生）都在 Job 内；停止 = `TerminateJobObject`，一次清光。
- **存活单位 = Job**：不看根进程是否退出。根进程退出后 2 秒退出去抖宽限期（等待"自重启"的新进程出现）；宽限期满 Job 内仍无进程，才判定真正退出。
- **状态机**：`Stopped → Starting → Running → Stopping → Stopped`，异常路径 `→ Faulted`。每脚本一把 `SemaphoreSlim(1,1)`，所有 Start/Stop/Restart 操作串行化。重启流程：获取信号量 → 停旧 Job → **确认 Job 内进程归零** → 等待 RestartDelay → 建新 Job。手动重启、资源超限、崩溃自愈、心跳超时四条路径共用同一重启流程，杜绝两个 Job 并存。
- **进程身份**：`(PID, 创建时间)`；文件名指纹扫描仅用于只读展示"外部进程"，**永不用于杀进程**（A6/A8）。

M3 落地备忘（均为实测踩坑，勿回退）：

1. **`JobObjectBasicProcessIdList = 3`，不是 1**（1 是 BasicAccountingInformation）。误传 1 时 API 恒返回 `ERROR_BAD_LENGTH(24)`，与缓冲区不足同码，极有迷惑性。
2. **`JOBOBJECT_BASIC_PROCESS_ID_LIST.NumberOfAssignedProcesses 是入参**：查询前必须把数组容量写入首 DWORD，`cb = 8 + N*sizeof(ULONG_PTR)`；进程数 > N 时才返回 24，容量按 ×4 倍增（上限 65536，防止异常时无限 AllocHGlobal 直到 OOM）。
3. **PID 列表会短暂滞留"退出中"进程**：每个 PID 用 `OpenProcess(QUERY_LIMITED_INFORMATION)+GetExitCodeProcess==STILL_ACTIVE(259)` 过滤，否则毫秒级脚本退出后仍被误判存活。
4. **查询失败 ≠ Job 空**：`SafeGetPids` 返回 `int[]?`，异常时为 `null`（含义未知），WatchLoop/停止等待对 null 一律继续等，绝不据此判空。
5. **启动时序**：`CreateProcessW(CREATE_SUSPENDED)` → `AssignProcessToJobObject` → `ResumeThread`，子进程从第一条指令起就在 Job 内。
6. **stdin 必须给有效句柄**：重定向时除 stdout/stderr 管道外另建一根 stdin 管道（读端可继承，父端立即关闭），否则 cmd 的 `start` 再派生命令会因复制到 NULL 句柄而失败。
7. **WatchLoop 重启段不能用旧 WatchCts 的 token**：判退出后 `CleanupUnderLock` 会取消旧 cts；随后的重启延时与取锁必须用**不可取消**的等待（`Task.Delay(...)` / `Gate.WaitAsync()` 无 token），否则 `OperationCanceledException` 被吞，重启永远不发生（M3 实测的自愈失效根因）。重启成功后旧循环显式 `return`，新循环由 `StartUnderLockAsync` 另起。
8. 崩溃后等待重启的空窗期（Job 已销毁）点"停止"：`StopUnderLockAsync` 登记 `UserIntendedStop=true`，重启段取锁后据此放弃。**注意（M5 真机缺陷 6）**：该方法签名是 `StopUnderLockAsync(rt, announceState=true, registerUserIntent=true)`——`RestartAsync` 停自己的旧实例时必须传 `announceState:false, registerUserIntent:false`，否则延迟后第 300 行（现同语义）的 `if (rt.UserIntendedStop) return;` 会把这次重启误判为用户停止，脚本延迟后永远不恢复。仅 StopAsync 与配置删脚本路径保持默认 true。
9. `CreateProcessW` 用经典 `[DllImport]`（STARTUPINFO 含 string 字段，LibraryImport 源生成不支持，报 SYSLIB1051）；其余 P/Invoke 用 `[LibraryImport]`。
10. **状态快照绝不允许在持锁路径内再次取 Gate（S3，勿回退）**：`SemaphoreSlim` 不可重入。锁内状态迁移（StartUnderLock/WatchLoop/StopUnderLock/TripCircuit/ResumeGuard）发事件一律用 `BuildSnapshotUnderLock`（不取锁）；只有外部查询 `GetStates()` 逐脚本 `Gate.Wait(2000)` 后调用它。旧实现锁内 Wait 曾导致每次启停固定自锁 2 秒、全套集成测试 3m16s；拆路径后 59s。
11. **重启生命周期与用户意图复核（M8 残余已修，勿回退）**：RestartAsync 取锁 → （运行中实例）以 registerUserIntent:false 停旧 Job 且不广播中间态 → **锁外**等 RestartDelay（此窗口用户可点停止置 UserIntendedStop 取消）→ 再取锁，若 UserIntendedStop 则放弃，否则 StartUnderLockAsync(isRestart:true)。延迟绝不能持锁等待。**清 UserIntendedStop 只允许手动重启（FaultReason.None）**；自动重启（资源/心跳，reason != None）第一次取锁时若发现 `UserIntendedStop && !IsAliveInstance`（监控锁外收集 id 后用户抢先停止的竞态）必须直接放弃，不得无条件清标志拉起已停脚本。

### 2.2 熔断（A7）

滑动窗口（默认 60 秒）内启动次数超阈值（默认 10 次，可按脚本覆盖）→ `Faulted`，暂停一切自动守护并告警；界面「恢复守护」后清零。心跳超时重启同样计入。

### 2.3 会话感知（A3/A9/P4，M4 已落地）

- **抽象**：`ISessionContext`（`GetActiveSessionId()` + `TryOpenUserToken(sid)`）两个实现：
  - `WtsSessionContext`（服务模式用）：`WTSGetActiveConsoleSessionId`（**kernel32.dll 导出**，非 wtsapi32）+ `WTSQueryUserToken`；令牌句柄用完即 Dispose。
  - `LocalSessionContext`（`--console` 与测试用）：活动会话恒为本进程 SessionId，令牌恒 null → 回退普通 `CreateProcessW` 同会话启动，**不排队**。
  - 选择点在 `SupervisionWorker.ExecuteAsync`，由进程级 `ServiceModeOptions.ConsoleMode` 决定（服务端务必显式用 WTS，不能吃默认值）。
- **启动路径**（`ScriptSupervisor.StartUnderLockAsync`，仅 `RunInSystemSession=false` 的脚本走）：
  1. 活动会话 < 0（无人登录）→ 置 `WaitingForSession=true`、状态保持 `Stopped`、发 Information 事件、返回 false；**不建进程、不占熔断窗口、不计重启**。
  2. 有会话：`TryOpenUserToken` 拿到令牌 → `CreateEnvironmentBlock`（在 SYSTEM 环境基础上叠加脚本自定义环境变量）→ `ProcessLauncher.LaunchAsUser`（CREATE_SUSPENDED→AssignJob→ResumeThread）；令牌拿不到（权限/时序）→ 回退同会话 `Launch`，本拍不致命。
- **桌面与窗口显隐（S2，勿回退）**：
  - `LaunchAsUser`（Session 0 → 用户会话）必须在 STARTUPINFO 显式 `lpDesktop = @"winsta0\default"`，否则子进程继承服务的非交互窗口站，GUI 用户看不见——这是双端架构核心目标；同会话 `Launch`（--console/RunInSystemSession）**不指定**桌面，继承当前窗口站。
  - 是否隐藏窗口按 **PE 可选头 Subsystem** 判定（`PeImageInfo.IsWindowsGui`：2=GUI、3=控制台，读损坏/缺失按控制台兜底）：控制台程序（cmd/powershell/ping/批处理宿主）给 `STARTF_USESHOWWINDOW+SW_HIDE` 与 `CREATE_NO_WINDOW` 防黑框；GUI 程序（notepad/Qt/WinForms/WPF）**两个标志都不能给**，否则首窗口可能被隐藏。注意 `.bat/.ps1` 脚本真正启动的是 cmd.exe/powershell.exe（CUI），GUI 由脚本自己再拉起的进程决定。
  - 该路径的 SYSTEM→真实用户桌面仍需在安装成服务后做一次真机验收（--console 同会话路径已验证 notepad 窗口可见）。
- **补发**：`SessionResumePoller` 每 5 秒轮询；仅当**会话 ID 变化且新会话令牌可打开**时调用 `ResumePendingForSessionAsync()`（遍历 WaitingForSession 且非 UserIntendedStop 且 Stopped 的脚本逐个启动）。令牌打不开本拍跳过且不更新 lastSessionId；活动会话复位为 -1 时同步复位，下一个用户登录仍能补发。排队期间手动"停止"会置 UserIntendedStop，登录后不补发。
- 每脚本 `RunInSystemSession=true` 时跳过整套逻辑，直接在服务会话（Session 0）启动（纯后台脚本）。
- SYSTEM 身份的 `CreateProcessAsUser` 路径无法在普通用户测试环境验证：由 `SessionResumeTests`（假 ISessionContext）覆盖排队/补发状态机，SYSTEM 令牌细节靠代码审查 + 真机安装验证。

#### 2.3.1 A9 会话归属规则（唯一表述，代码以此为准）

1. **控制端连接后必须发 `subscribe`，并在载荷里声明自己所在的会话 ID**（`SubscribePayload.sessionId`）；命令本身不带会话归属，全部由服务端按脚本配置与活动会话决策。
2. **命令类消息**（启停/全部停止等）是全局权威操作，不受会话限制——任何通过 ACL 的已订阅连接都可执行，因为管道本身已经把非授权主体（Network/Anonymous）挡在外面。
3. **事件类消息的投递规则**（与 `IpcServer.BroadcastLoopAsync` 严格对应）：
   - `scriptStates`（状态快照广播）：投给所有已订阅连接，不按会话过滤（列表按脚本快照里的 `sessionId` 字段各自展示归属）；
   - `notify`（故障/信息通知）：活动控制台会话 ≥ 0 时，只投给订阅声明的 `sessionId` 等于活动会话的连接；声明 `null` 的连接照收（系统级/调试消费者）；活动会话 < 0（无人登录）时不过滤，全部照发；
   - `scriptOutput`：只看订阅时的 `includeOutput=true` 标记，不做会话过滤。
4. 快速用户切换场景：旧用户断开后其控制端连接随之关闭，通知自然只投到新活动会话；脚本归属仍以快照 `sessionId` 展示，不错杀、不串台。

### 2.4 IPC（A2，M4 已落地）

- 一条管道连接同时承载 `{请求→响应}` 与服务端主动事件推送，按 `requestId` 是否为空区分。
- 管道名 `StartupTool-v1`（`\\.\pipe\StartupTool-v1`），服务端多实例 `MaxAllowedServerInstances` + 每连接独立 ClientSession。
- **ACL**（`PipeSecurityFactory.Create(bool interactiveServer)`，`NamedPipeServerStreamAcl.Create` 直接使用，net10 下勿再引 System.IO.Pipes.AccessControl 包）：
  - 先 `SetAccessRuleProtection(true,false)` 去掉继承；
  - SYSTEM、Administrators 完全控制（含 CreateNewInstance——生产服务自身需要）；
  - **Interactive 生产模式只授 ReadWrite（M3，勿再给 CreateNewInstance）**：否则任意交互用户可自建同名管道实例抢占/仿冒服务端。仅当服务端本身以交互用户身份运行（--console 调试、集成测试）时传 `interactiveServer:true` 补回建实例权——IpcServer 构造参数，SupervisionWorker 按 ServiceModeOptions.ConsoleMode 接线，生产服务固定 false；
  - Deny NetworkSid（ReadWrite）与 **AnonymousSid**（FullControl；注意枚举名就是 AnonymousSid）；
  - 因此服务在 Session 0 建的管道，登录用户能连，网络/匿名身份连不上——授权不依赖会话枚举。
- **背压与稳定性**：监管线程只往有界 Channel（容量 512，满了丢最旧事件）投递，绝不阻塞 supervisor；每连接一把写锁，单次写入 5 秒超时，慢/断客户端直接 Dispose 不拖累其他连接。
- **帧长上限读写两端一致（M16）**：PipeFrame.MaxFrameSize=1MB（internal），ReadAsync 拒收超长帧，WriteAsync 序列化后先校验、超限抛 InvalidDataException **一个字节都不发**。新增消息类型时若可能超 1MB（如大批量输出行），必须在协议层分页。
- **广播并行扇出（M17）**：DispatchBroadcastAsync 先按 Subscribed/IncludeOutput/会话过滤出目标客户端，再 `Task.WhenAll` 并行 TryWriteAsync——每客户端独立 Stream+写锁，严禁回退成 foreach 串行 await（一个慢客户端 5s 会阻塞同轮所有订阅者的推送）。
- **广播线程生命周期（S5，勿回退）**：① `TryWriteAsync` 的 `WriteLock.WaitAsync` 必须在 try 内，catch 兜住 ObjectDisposedException/SemaphoreFullException，连接拆除期间绝不让异常逃出广播循环；② `HandleClientAsync` 的 finally 顺序固定为「先从 `_clients` 摘表 → 等待在途广播写出结束（最多一个写超时）→ 再 Dispose 写锁与管道」，写锁先 Dispose 会直接杀死广播线程；③ `BroadcastLoopAsync` 对每条广播整体 try/catch（拆出 `DispatchBroadcastAsync`），单条/单客户端异常只丢本条。广播线程死掉的症状是"服务仍在守护、界面状态永久冻结"，只能重启服务。
- **连接级空闲超时与保活（S6）**：服务端对每连接施加"两帧之间 60 秒"空闲读超时（每读完一帧重置，构造参数 idleTimeout 可注入用于测试），防止只连不发占满 254 个管道实例；`IpcClient` 配套每 20 秒发一次 `ping` 保活（间隔可注入），Ping 失败即 Dispose 管道，由 AppClientService 的 ConnectLoop 重建连接。`--beat` 是一次性收发短连接，不受影响。
- **通知可过滤、状态必达（M5 真机缺陷 8）**：`ForwardingSink` 对 StateChanged 只入 StatesBroadcast；对 Fault/Information 在入 NotifyBroadcast 之后**再无条件补一个 StatesBroadcast**。notify 受 NotifyOnFault 开关和会话过滤，states 永远广播——否则熔断时 UI 只收到可能被过滤的气泡、状态行永远停在"已停止"。
- **upsertScript 字段合并语义（N1/N3，勿回退为整对象替换）**：Id 不存在=新建追加队尾；**已存在=字段合并**——服务端权威/编辑窗未暴露字段（Order、HeartbeatToken、DependsOn、RequireElevation、InitialDelaySeconds、WaitForNetwork）一律保留服务端现值，只接受编辑窗可编辑字段。HeartbeatToken 在任何路径都不接受客户端值（新建置空，由 getHeartbeatToken 按需生成；更新保留原值），令牌只能由 getHeartbeatToken/resetHeartbeatToken 产生。今后编辑窗新增字段录入时，必须同步把该字段移出服务端保留清单。客户端侧另有一道防线：MainViewModel.EditAsync 在本地配置未命中时强制重拉一次，仍失败则拒绝开窗（不再用 {Id,Name} 残缺兜底）。
- **updateSettings 服务端白名单（N2）**：落盘前必过 `GlobalSettings.Validate()`——LogMaxSizeMb 1–1024、LogRetentionDays 1–3650、CircuitWindowSeconds 1–86400、CircuitMaxStarts 1–1000、Language ∈ {null, zh-CN, en, system}；非法回 invalidPayload 且不写配置。注意 Language=null（跟随系统）经 ConfigJson 的 WhenWritingNull 克隆/落盘往返后会落为模型默认 "zh-CN"（已知低优先瑕疵，待修）。
- **单例激活（B8）**：与管道无关，由 `SessionSingleton` 用**每会话隔离的内核对象**实现（`Local\StartupTool.App-v1` Mutex + `Local\StartupTool.App-v1.Show` AutoReset 事件），第二实例发事件后退出，首实例收到事件唤起窗口——不再依赖窗口标题，语言切换不受影响。
- 帧 = 4 字节小端 int32 长度前缀 + UTF8 JSON（`PipeFrame`）；JsonOptions：camelCase + JsonStringEnumConverter + UnsafeRelaxedJsonEscaping。

### 2.5 配置（A10/B1/B19，M2）

- 原子写：同卷临时文件 → `File.Replace(tmp, target, .bak)`；文件不存在时 `File.Move`。
- 热重载：FileSystemWatcher + 250ms 防抖；**解析失败保留旧内存值**并发 `ConfigLoadFailed` 事件，绝不重置；成功才替换并发 `ConfigChanged`。
- **启动期容错（M5）**：构造函数中 v1→v2 迁移落盘失败**不得抛出**——磁盘只读/占用时内存迁移结果照常运行（否则服务和控制端整体起不来），失败文本暴露在 `InitialSaveError`，磁盘保持旧 v1，下次启动重试；`InitialLoadError`（损坏文件）同理。SupervisionWorker 启动时把两者写 stderr。运行中用户主动 Mutate 写失败仍照常抛给调用方（IPC 返回失败），不吞。
- **Id 唯一（M6）**：Normalize 是所有配置进入内存的唯一入口，它保证每个脚本 Id 非空且唯一：空 Id/重复 Id（首个保留，其余新分配 Guid）在此纠正；下游 ToDictionary 再用 GroupBy 兜底。手改 scripts.json 造成重复 Id 曾让资源巡检整轮静默失效。
- 自己的写入通过内容哈希比对忽略，避免回环。
- v1→v2 迁移：`Enabled` 拆成 `AutoStart + ManualEnabled`，生成 Id；丢弃 `RunMode/WebPort`；首次迁移后原子落盘 v2。
- ACL：保存后对 scripts.json 设保护，仅 SYSTEM/Administrators 访问（含心跳令牌，H2）。**M2 起目录一并收紧**：`ConfigFileSecurity.ProtectDirectory` 对配置目录断继承、授 SYSTEM/Admins 可继承全权（ContainerInherit|ObjectInherit），目录内新建 .tmp/.bak 不再有继承自父目录的权限空窗；文件级 Protect 仍逐次执行作为双保险。保护返回 bool：非提权环境（如开发机 --console）收紧失败时**不阻断运行但必须上报**——ConfigService.AclProtectionFailed 事件（锁外触发）+ AclProtectionActive 属性，SupervisionWorker 订阅写 stderr；服务以 SYSTEM 运行时不会失败。
- 心跳令牌比较（M4）：`FindByHeartbeatToken` 用 `CryptographicOperations.FixedTimeEquals`（UTF8 字节）定长比较，不要退回 string.Equals 的逐字符短路。

### 2.6 日志（B9/B10/B11/B15；F5 已落地实现）

`Core/Logging/LogStore.cs`：服务日志 `logs\service\service-yyyyMMdd.log`；脚本日志 `logs\scripts\<净化名>_<Id 前 8 位>\output-yyyyMMdd.log`。

- 写入时**每次现取** `GlobalSettings`（`logMaxSizeMb` / `logRetentionDays` 热重载即时生效），越界值按 1–1024 MB / 1–3650 天夹取。
- 当天文件达到上限即分片（`…-2.log`、`…-3.log`…；序号兜底上限 10000 后改按时刻命名，绝不无限循环）。保留天数清理在服务启动时执行一次，之后每次写入按日复核一次。
- 全路径 `lock` 串行 + 异常全吞：日志写失败绝不影响守护。只写 Fault/Information/ScriptOutput 与启动期警告，**不写 StateChanged**（每拍状态迁移会淹没故障记录）。
- Service 侧由 `LoggingEventSink` + `TeeEventSink` 接入（同一事件同时送 IPC 广播与日志落盘），见 §7.2。

### 2.7 资源监控与外部进程（M3，B2/B3/B5/B13/A8）

- `ResourceSampler`：CPU 用 `Process.TotalProcessorTime` 差分；GPU 用性能计数器 `\GPU Engine(*)\Utilization Percentage`，实例名形如 `pid_1234_luid_..._phys_0_eng_0_engtype_3D`。**engtype 是字符串记号（S4，勿回退为 int 解析）**：`3D`/`VideoDecode`/`VideoEncode`/`Compute`/`Copy` 等，取最后一个 `_engtype_` 之后的原文；先按 (pid, engType) 取同引擎最大，再跨引擎类型取最大（贴近任务管理器口径）；采集不到返回 `null`，界面显示 N/A（B3）。不保留任何跨 PID 累积状态（B13）。
- `ResourceMonitor`：独立 5 秒定时，**每轮重新读取配置中的阈值**（B5）；超限调用统一 `RestartAsync(id, ResourceLimit)`。**外部进程扫描每轮只做一次（M10）**：对全部 Running 脚本一次 WMI 全量 Scan，再按结果的 ScriptId 分组计数——旧实现在循环内每脚本 Scan 一次，N 脚本=N 次 Win32_Process 枚举；无运行脚本时完全不发 WMI 查询。
- `ExternalProcessScanner`：一次 WMI（`SELECT ProcessId,Name,ExecutablePath,CommandLine FROM Win32_Process`）批量取全量并排除 Job 内 PID；**匹配规则（M11 收紧，勿回退为文件名子串）**：① exe 完整路径与脚本路径完全相等（去引号归一、大小写不敏感）；② 命令行包含脚本完整路径（手动双击 .bat/.ps1 的 cmd/powershell 包装场景）。旧的"文件名长度>3 即 Contains"会把 node.exe/python.exe 等同名解释器及参数中偶然提到文件名的无关进程大面积误报，已删除；代价是经 PATH 解析、命令行不含脚本全路径的调用可能漏报（宁可漏报不误报，符合 A6/P6）。同路径外部进程被多个脚本引用时对每个脚本都产出记录（M5 修复，不 break）。`TryKill` 三重保护（托管集合排除+重扫定位+(PID,创建时间)校验），默认永不自动杀（A8）。

### 2.8 心跳接线（M3）

`HeartbeatMonitor`（5 秒定时）→ `ScriptSupervisor.CollectHeartbeatTimeouts(now)` 取超时 id 列表 → 调用方在锁外逐个 `RestartAsync(id, HeartbeatTimeout)`；判定与管道收发完全解耦。M4 管道端落地后，`--beat` 经 IpcServer.HandleBeat 端到端验证通过（退出码 0/10/11/12/13 实测）。**M9 补齐运行态语义**：`Beat()` 仅当实例存在且 `State==Running` 才记 LastBeatAtUtc 并回 Ok；实例不存在或 Stopped/Starting/Stopping/Faulted 回 `BeatResult.NotRunning`（取锁超时保守回 Ok，避免状态迁移瞬间误判）；IpcServer 映射 ack code `notRunning`，BeatClient→BeatTransportResult.NotRunning，`--beat` 退出码 **15**。脚本可据此发现"服务端已停掉自己"（如被用户停止/熔断后残留的定时心跳）。

### 2.9 M4 实测踩坑备忘（勿回退）

1. **`WTSGetActiveConsoleSessionId` 在 kernel32.dll**，不在 wtsapi32.dll；写错 DLL 编译不报错，首次调用才抛 `EntryPointNotFoundException`（--console 实测首杀）。
2. **WinExe 子系统也会被当"控制台模式"启动**：无控制台句柄时 `Console.Title=` 抛 IOException"句柄无效"，所有 Console 写都要 try/catch；不能假设 --console 一定带着真控制台。
3. **--console 必须用 LocalSessionContext**：SupervisionWorker 若吃 ScriptSupervisor 的默认构造参数（恰好是 Local），在服务模式里就会退化成"SYSTEM 同会话启动"且永不排队。模式选择集中在 ServiceModeOptions，服务=WTS、console=Local，不依赖构造默认值。
4. **net10 不要再引 System.IO.Pipes.AccessControl**（已内建，NU1510）；枚举名是 `WellKnownSidType.AnonymousSid`、`NamedPipeServerStream.MaxAllowedServerInstances`；NamedPipeServerStreamAcl.Create 用命名参数后后续参数也必须命名。
5. **事件接线是 sink 不是内部直连**：supervisor 先于 IpcServer 构造，生产用 RelayEventSink（Target 后置），集成测试也必须装 relay 并把 Target 指向 `ipcServer.EventSink`，否则请求全通但事件永远收不到。
6. **EventWaitHandle.OpenExisting 没有 out created 重载**，单例用 try/catch `WaitHandleCannotBeOpenedException`；互斥/事件统一 `Local\` 前缀做每会话隔离（B8）。
7. **sc.exe 命令必须 Arguments 字符串原样传**（不能用 ArgumentList 重转义），binPath 值写法 `binPath= "\"{exe}\" --service"`；ServiceInstaller 命令构造为 internal 单测覆盖。**失败重启策略 reset 必须是非 0（M12）：`reset= 86400`（24 小时）——reset=0 会让 SCM 失败计数永不归零，三轮崩溃后服务永不再自动重启。**
8. **安装器结果必须可信（M13/M14）**：Install 先做 `IsRunningElevated` 管理员预检（非提权直接退 5）；描述/失败策略/登录自启等可选步骤失败只记警告并在结束语汇总，**启动服务失败必须返回 21，不能仍报"完成"**。RunSc 读 sc.exe 输出必须先 `ReadToEndAsync` 排空 stdout/stderr 再 WaitForExit，防止 stderr 写满管道形成死锁；30 秒超时 Kill 整树。退出码约定：5=未提权、20=exe 不存在、21=已注册但启动失败。
9. **ps1 含中文必须存 UTF-8 BOM**，否则 Windows PowerShell 5 按 ANSI 读脚本会乱码。
10. **WinExe 拿退出码**：PowerShell `& exe` 对 GUI 子系统程序可能拿不到 `$LASTEXITCODE`，自动化测试/脚本用 `Start-Process -Wait -PassThru` 读 ExitCode。
11. **真实进程测试关闭 xUnit 并行**：管道、Job、cmd.exe 创建在高负载机器上互拖，时序断言（如 30s 熔断窗口）会假失败；`[assembly: CollectionBehavior(DisableTestParallelization = true)]`。
12. **PID 存活判定（M7，勿回退）**：`JobObject.IsProcessAlive` 中 OpenProcess 失败时只有 `GetLastWin32Error()==ERROR_INVALID_PARAMETER(87)` 才判已退出（实测 PID 0/已退出 PID 均返回 87）；ACCESS_DENIED 等其他错误**按存活处理**——误判一个 Job 已空会错误触发重启/清理，宁可让 WatchLoop 双周期复查多等一拍。
13. **测试项目引用 App（M18）**：测试 csproj 加 App 的 ProjectReference 后必须开 `<UseWPF>true</UseWPF>`，但 WPF 桌面 SDK 的隐式 using 是精简集（只有 System/Linq/Threading 等，**没有 System.IO/System.Diagnostics**），需在 csproj 用 `<Using Include=...>` 显式补回；App 侧用 `<InternalsVisibleTo Include="StartupTool.Core.Tests" />` 暴露 Program/BeatCommand。Program.Main 是 private，分流测试用反射调用，只测安全快速的 --beat 路径，无参 WPF/--service 阻塞路径不直调。

### 2.10 M5 WPF 控制端踩坑备忘（勿回退）

1. **本地化语言码 ≠ 资源文件名（真机缺陷 7）**：逻辑语言码是 `zh-CN`/`en`，资源文件是 `Strings.zh-CN.xaml`/`Strings.en-US.xaml`，必须经 `LocalizationService.DictionaryFiles` 映射拼 pack URI，不能直接 `Strings.{language}.xaml`（中文恰好一致才没暴露）。切换顺序：先构造并加载新字典 `next`，成功后再 Remove 旧的、Add 新的；加载失败保留旧语言，避免整界面文案丢空。
2. **任何 ShowDialog 都必须发生在主窗口 Hide() 之前（真机缺陷 9）**：owner 隐藏后，模态子窗不可见且不在任务栏，表现为窗口消失、进程卡在不可见模态框，托盘也唤不醒，只能杀进程。Window_Closing 顺序固定为「弹 ConfirmWindow（含"不再提醒"写 client.json）→ 对话框关闭 → 最后 Hide()」。托盘「退出控制端」路径目前仍是对隐藏 owner 弹 Confirm（第二轮检查 N4，未修），真机若复现假死需同样处理（临时 owner=null 或先恢复主窗）。
3. **MVVM 线程封送**：管道事件在 App.xaml.cs 统一 Dispatcher 封送；脚本输出走 ConcurrentQueue + DispatcherTimer 排空，绝不在后台线程改 ObservableCollection。
4. **偏好分工**：语言 / NotifyOnFault 存服务端 scripts.json 的 GlobalSettings（多端一致）；窗口尺寸、HideToTrayHintDismissed 等纯本机 UI 偏好存 `%LOCALAPPDATA%\StartupTool\client.json`。
5. **ContextMenu 不在可视树**：托盘菜单在 Opened 时显式赋 DataContext；行菜单通过 PlacementTarget.DataContext 取行、命令 Source 用 x:Reference 回 DataGrid。
6. **编辑保存语义（产品决策 5）**：守护类属性（资源阈值/心跳/重启策略等）保存即下一拍生效；启动类属性（路径/参数/环境变量等）在脚本运行中保存后弹【立即重启】【稍后手动重启】，停止态保存不弹。

### 2.11 进程启动其他细节（M5）

- **输出管道句柄继承位（真机缺陷 3 / 检查 S1）**：`CreatePipe(..., NULL, 0)` 两端默认**都不可继承**；必须显式把交给子进程的 stdout/stderr 写端与 stdin 读端置可继承，父持有的读端/写端清继承位；父端写端在 CreateProcess 后立即 Dispose，否则读端永不 EOF。
- **输出编码（真机缺陷 5）**：`OutputLineReader` 逐行解码，先严格 UTF-8，失败回退当前 OEM 代码页（中文系统 936/GBK）；不要加 System.Text.Encoding.CodePages 包（.NET 10 已内置，强引报 NU1510）。
- **默认工作目录（M1 已修，勿回退）**：未配置 WorkingDirectory 时一律取**脚本文件所在目录**（LaunchOptions.ScriptPath=cfg.Path，ProcessLauncher.ResolveWorkingDirectory：显式配置→脚本目录→宿主 exe 目录）。旧实现取宿主可执行文件目录，.bat 经 cmd.exe 启动会落到 System32、.ps1 落到 PowerShell v1.0，脚本内相对路径全部错位。
- **Python 解释器路由（D10，勿回退）**：`.py/.pyw` **绝不能**落进默认分支直接 `CreateProcess(脚本路径)`——Windows 不认该可执行格式，必然启动失败。`CommandLineBuilder.Build` 对该扩展名单独路由：`script.PythonExecutable`（编辑窗【Python 解释器】）非空时**原样使用**（典型值 = 虚拟环境的 `Scripts\python.exe`，**无需 activate**，目录名任意）；为空则 `ResolveExecutable("py.exe")` → `python.exe` 兜底。**指定了就不静默回退**：否则用户以为在用 venv、实际用了全局环境，缺依赖时更难排查。参数串固定为 `"<脚本路径>" <用户参数>`。

### 3.1 ConfigService 关键实现备忘

- 写入：`Mutate(Action<AppConfig>)` 在锁内深拷贝 → 修改 → Normalize → 临时文件 + ACL → `File.Replace`（带 `.bak`）→ 替换内存 → 锁外发 `Changed`；哈希记录用于抑制自身 watcher 回环。

## 4. IPC 协议（M4 实际版本）

帧：`[int32 LE 长度][UTF8 JSON]`。信封：`{type, requestId, payload}`——请求必带 requestId；服务端主动事件 requestId 为空。

### 4.1 消息类型（`IpcTypes` 常量）

| 方向 | type | 载荷 | 说明 |
|---|---|---|---|
| C→S | ping | — | 连通性探测，回 Ack |
| C→S | subscribe | `{sessionId?, includeOutput}` | 订阅事件；声明控制端所在会话（A9，见 2.3.1） |
| C→S | getStates | — | 回 `scriptStates` 全量快照（非事件，带 requestId） |
| C→S | startScript / stopScript / restartScript | `{scriptId}` | 单脚本命令；start 被拒绝（排队/熔断/禁手启）回 `{ok:false,code:"rejected"}` |
| C→S | startAll / stopAll | — | startAll 只启 ManualEnabled 脚本 |
| C→S | resumeGuard | `{scriptId, startNow}` | 熔断恢复（M5 界面接线） |
| C→S | beat | `{token, timestampUnixSeconds}` | 一次性心跳；回 Ack，ok=false 时代码为 invalidToken / clockSkew / notRunning（notRunning 客户端归入 ProtocolError→退出码 14） |
| C→S | upsertScript / deleteScript / reorderScripts / resetHeartbeatToken / importConfig / exportConfig / exportDiagnostics | 各自 payload | 配置类：M4 服务端回 `notSupported`，M5/M6 落地 |
| S→C | ack | `{ok, code?, error?}` | 通用应答 |
| S→C | scriptStates | `{scripts: ScriptRuntimeSnapshot[]}` | 响应 getStates 或状态变化广播 |
| S→C | notify | `{kind, scriptId, scriptName, message, atUtc}` | kind=`fault`/`information`；投递规则见 2.3.1 |
| S→C | scriptOutput | `{scriptId, scriptName, line, atUtc}` | 仅 includeOutput 订阅者 |
| S→C | configData | `AppConfigPayload` | 响应 getConfig；**F8 起也作事件帧**（requestId 为空）：外部改盘热重载后主动推送整份配置 |

### 4.2 客户端实现

- `IpcClient`：长驻单连接客户端，请求/响应按 requestId 的 TaskCompletionSource 配对，默认 15 秒超时；无 requestId 的入帧转 `EventReceived` 事件；断开触发 `Disconnected`（控制端 AppClientService 3 秒重连，重连后自动重新 subscribe 并拉首屏）。
- `BeatClient`：一次性同步客户端，连接总超时 3 秒，映射 `Delivered/NoServer/InvalidToken/ClockSkew/NotRunning/ProtocolError`，由 `BeatCommand` 转退出码 0/11/12/13/15/14。

## 5. 心跳模块（H 类）——《脚本心跳包发送要求》

### 5.1 协议要求

1. 命令行：`StartupTool.exe --beat <令牌> <Unix秒时间戳>`，参数个数必须恰好为 2（令牌 64 个十六进制字符）。
2. 进程行为：作为管道客户端连接服务端 → 发送 `Beat` 帧 → 读取 `Ack` → 退出。连接/等待总超时 3 秒，**绝不长驻、绝不阻塞脚本业务**（H7）。
3. 服务端校验顺序：管道 ACL → 令牌存在且有效 → `|服务端时间 - 时间戳| ≤ 300` → 更新该脚本 `LastBeatAt = 服务端时间`。
4. 心跳包**只含存活语义**，不解析、不存储任何业务字段（H4）。
5. 判定：脚本 `HeartbeatEnabled=true` 且进入 Running 后开始监控；启动宽限期 = 超时×2；监控为**独立定时任务**，每 5 秒扫一次；`Now - LastBeatAt > 超时` 即超时 → 走标准重启流程并记录原因"心跳超时"。令牌在脚本每次启动时不变（重置令牌除外），`LastBeatAt` 在启动时清零。
6. 安全：令牌 = 32 字节随机数十六进制（`RandomNumberGenerator`）；存配置文件受 ACL 保护；「重置令牌」立即作废旧令牌。

### 5.2 退出码（脚本可据此判断发送结果）

| 退出码 | 含义 |
|---|---|
| 0 | 服务端已确认收到 |
| 10 | 参数错误（用法不对/令牌格式错/时间戳非数字） |
| 11 | 无法连接服务（服务未运行或管道不可用） |
| 12 | 令牌无效或已被重置 |
| 13 | 时间戳超差（本机时间与服务端相差超过 300 秒） |
| 14 | 超时/IO 错误 |
| 15 | 令牌有效但脚本当前未运行（M9：已被停止/熔断/尚未启动；残留定时心跳应据此自我了断或告警） |

### 5.3 脚本示例（与 D9 模板库、项目文档 §5.3 同源，可直接复制）

> 三份脚本内容即 D9 内置的 `HeartbeatBat` / `HeartbeatPowerShell` / `HeartbeatPython` 模板的脚本文本，
> 改动模板时必须同步更新这份文档与《项目文档.md §5.3》，保持一致。

**发送要求（写进脚本的要点）**

1. **填两处关键值**：`StartupTool.exe` 的完整路径、控制端「心跳」窗口复制的 64 位十六进制令牌。
2. **每轮循环发送一次**：命令形如 `--beat <64位hex> <Unix秒>`；时间戳必须每次现取当前值，不要赋死。
3. **判别发送结果**：以进程/命令**退出码**为准——`0` 表示服务端已确认收到；非 `0` 表示本次未投递成功，
   应打印告警（并说明退出码含义，见 §5.2）后**停止发送**，避免脚本已不被守护时无限空转刷新日志。
   特别地，退出码 `15` 表示"令牌有效但脚本当前未运行"（已被停止/熔断/尚未启动），此时应主动停发或告警。
4. **时间戳取值**：用目标语言取 `Unix 秒`（见各示例）；偏差超过 300 秒会被服务端拒收（退出码 13）。
5. **休眠**：建议用能干净退出的方式（PowerShell `Start-Sleep` / Python `time.sleep`）；批处理用
   `ping -n <秒+1> 127.0.0.1 >nul` 代替 `timeout`，避免无交互会话下报错（`-n` 的 1 秒会占用第 1 个计数）。

**bat（HeartbeatBat）**

```bat
@echo off
setlocal
rem ============================================================
rem  StartupTool 脚本心跳发送示例（批处理）
rem  把 BEAT_PATH 与 TOKEN 换成你的实际值：
rem   - BEAT_PATH：StartupTool.exe 的完整路径
rem   - TOKEN：控制端「心跳」窗口复制的 64 位十六进制令牌
rem  每 30 秒发送一次心跳；退出码非 0 即打印告警并停止发送。
rem ============================================================
set "BEAT_PATH=C:\path\to\StartupTool.exe"
set "TOKEN=REPLACE_WITH_YOUR_64_HEX_TOKEN"
set "INTERVAL_SECONDS=30"

:loop
    rem 取 Unix 秒时间戳（用 PowerShell 计算，兼容 Win10+）
    for /f %%t in ('powershell -NoProfile -Command "[DateTimeOffset]::UtcNow.ToUnixTimeSeconds()"') do set "TS=%%t"

    "%BEAT_PATH%" --beat "%TOKEN%" "%TS%"
    if errorlevel 1 (
        echo [心跳] 发送失败，退出码 %errorlevel%，停止发送。
        goto :eof
    )

    rem 用 ping 休眠，避免 timeout 在无交互会话下报错
    ping -n %INTERVAL_SECONDS% 127.0.0.1 >nul 2>&1
goto loop
```

**PowerShell（HeartbeatPowerShell）**

```powershell
# ============================================================
#  StartupTool 脚本心跳发送示例（PowerShell）
#  把 $BeatPath 与 $Token 换成你的实际值：
#   - $BeatPath：StartupTool.exe 的完整路径
#   - $Token：控制端「心跳」窗口复制的 64 位十六进制令牌
#  每 30 秒发送一次心跳；退出码非 0 即打印告警并退出。
# ============================================================
$BeatPath = "C:\path\to\StartupTool.exe"
$Token    = "REPLACE_WITH_YOUR_64_HEX_TOKEN"
$Interval = 30

while ($true) {
    $ts = [DateTimeOffset]::UtcNow.ToUnixTimeSeconds()
    & $BeatPath --beat $Token $ts
    $code = $LASTEXITCODE
    if ($code -ne 0) {
        Write-Host "[心跳] 发送失败，退出码: $code，停止发送。" -ForegroundColor Yellow
        break
    }
    Start-Sleep -Seconds $Interval
}
```

**Python（HeartbeatPython）**

```python
# ============================================================
#  StartupTool 脚本心跳发送示例（Python）
#  把 BEAT_PATH 与 TOKEN 换成你的实际值：
#   - BEAT_PATH：StartupTool.exe 的完整路径
#   - TOKEN：控制端「心跳」窗口复制的 64 位十六进制令牌
#  每 30 秒发送一次心跳；退出码非 0 即打印告警并退出。
# ============================================================
import subprocess
import time

BEAT_PATH = r"C:\path\to\StartupTool.exe"
TOKEN = "REPLACE_WITH_YOUR_64_HEX_TOKEN"
INTERVAL = 30

while True:
    ts = int(time.time())
    proc = subprocess.run(
        [BEAT_PATH, "--beat", TOKEN, str(ts)],
        capture_output=True,
        text=True,
    )
    if proc.returncode != 0:
        print(f"[心跳] 发送失败，退出码: {proc.returncode}，停止发送。")
        break
    time.sleep(INTERVAL)
```

### 7.3 心跳窗崩溃与绑定模式备忘（F9，2026-10-20，改 XAML 绑定前必读）

"" : …`，无 setter）。**WPF 中 `TextBox.Text` 的绑定默认模式是 `TwoWay`**（因为 `TextBox.TextProperty` 的 `FrameworkPropertyMetadata` 带 `BindsTwoWayByDefault`），绑定引擎在 `BindingExpression.AttachToContext` 会把"源属性只读 + TwoWay"判为非法并抛 `InvalidOperationException`（"无法对…只读属性…进行 TwoWay 或 OneWayToSource 绑定"）。该异常由 `DataBindEngine` 在 **layout-updated** 回调里抛出（不是在窗口 `InitializeComponent` 时），应用未挂 `DispatcherUnhandledException` → 进程被直接终止、无 WER 对话框，只留事件日志 1026。**加 `IsReadOnly="True"` 并不能免除 TwoWay 要求**——默认模式只看 DP 元数据，与控件是否可编辑无关。

### 7.4 ComboBox 选中框本地化与固定列宽备忘（F10，2026-10-20，改控件模板/表格列前必读）

- **ComboBox 选中框不走 ItemTemplate 的坑（勿回退）**：自定义 `ComboBox` 的 `ControlTemplate` 时，选中框（关闭态显示的 `ContentPresenter`）**必须同时绑 `Content` 与 `ContentTemplate`**：

### 7.5 登录自启隐藏 / 表格列宽预算 / 脚本启动前置条件（F11，2026-10-21，改启动流程或加列前必读）

- **`--minimized` 的实现顺序（勿改）**：`tb:TaskbarIcon` 定义在 `MainWindow.xaml` 的可视树里，托盘图标在窗口内容 **Loaded 时**才创建。因此**绝不能在 `Show()` 之前就 Hide 或干脆不 Show**——否则图标不存在，用户再也唤不出窗口（进程活着但无入口）。正确顺序：构造期 `Opacity=0` + `ShowInTaskbar=false`（抑制首帧闪现）→ `Show()` → `Window_Loaded` 里 `Dispatcher.BeginInvoke(DispatcherPriority.Loaded, HideOnStartup)` → `Hide()` 并复位 `Opacity=1/ShowInTaskbar=true`。`RestoreFromTray()` 显示前同样复位这两项，否则从托盘唤起时会是"隐形窗口"。
- **Run 键带参**：登录自启由安装器 `ServiceInstaller.TrySetClientAutoRun` 写 HKLM Run，值必须是 `"<安装路径>\StartupTool.exe" --minimized`。手工排查时可用 `(Get-ItemProperty "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Run" -Name StartupTool).StartupTool` 核对。
- **DataGrid 列宽预算（加列前必算）**：默认窗口 `Width=1180`（逻辑）下，表格可视宽 ≈**1108**（扣卡片/表格外边距与竖直滚动条），125% DPI 下物理约 1385。所有固定宽列之和必须显著小于该值，否则 `Width="*"` 的列会被压成 **0（列头直接消失）**。当前固定列合计 ≈**863**（名称120/状态100/PID55/会话55/运行时长70/重启50/CPU55/内存65/GPU55/最后心跳75/外部进程70/退出码55）+ 操作列 Auto≈200。**新增列前先算总量**，或给 `Width="*"` 列加 `MinWidth` 让窗口变窄时出横向滚动条而不是把列压没。空值统一用 `TargetNullValue=—` 显示占位符，避免"空白=内容丢失"的误判。
- **脚本启动的三个前置条件（排查"无法启动"先查这三项）**：
  1. **会话归属**：勾了「在服务会话（Session 0）中运行」后，脚本在 SYSTEM 的 Session 0 执行——**那里没有交互桌面**，任何需要窗口/桌面/剪贴板/输入注入的程序都会失败（典型报错 `No active interactive desktop for physical input control`）。GUI 或有桌面依赖的脚本必须取消勾选，改在登录用户桌面运行。
  2. **心跳必须由脚本自己发**：「启用应用层心跳」不是"自动探活"，而是要求脚本按 §5 定期调用 `StartupTool.exe --beat <令牌> <Unix秒>`。脚本不发心跳 → 超过 `HeartbeatTimeoutSeconds` 就会判定卡死并杀掉重启（日志转圈「心跳超时（90 秒未收到心跳），将重启」）。**未接心跳的脚本不要开该开关。**
  3. **批处理末尾的 `pause`**：会让失败的脚本"看起来还活着"（不退出、拿不到退出码），从而绕过崩溃自愈判定、最终只能被心跳超时杀掉。放进 StartupTool 托管的 .bat 不要保留 `pause`。
- **本机取证命令**：脚本自身输出在 `logs\scripts\<名称>_<Id前12位>\output-yyyyMMdd.log`（UTF-8，PowerShell 需 `[System.IO.File]::ReadAllText($f, [Text.Encoding]::UTF8)`），服务端事件在 `logs\service\service-yyyyMMdd.log`（只写 Fault/Information/脚本输出，**不写 StateChanged**，所以"日志为空"通常等于"没有故障事件"，不是没写盘）。

### 7.6 Python 解释器字段与托盘应用图标（D10/F12，2026-10-21，改脚本路由或托盘图标前必读）

- **字段链路**：`ScriptConfig.PythonExecutable`（`string?`）→ `ScriptEditViewModel.PythonExecutable`（`string`，空串=未指定）→ `ScriptEditViewModelCloner.ApplyEditable` 写回（空白 Trim，全空存 `null`）。服务端 `HandleUpsertScript` 采用"整对象 + 仅保留 `Order`/`HeartbeatToken`"，因此**无需**把该字段加进保留白名单；但若将来改成服务端权威字段，必须同步加进 `IpcServer` 的保留清单，否则会被客户端覆盖。
- **只在 Python 分支解析**：`.bat/.cmd/.ps1` 完全忽略该字段，不要在 `Build` 入口提前解析它（避免对非 Python 脚本做无意义的路径处理）。
- **不静默回退**：`ResolvePythonInterpreter` 对已指定值仅做 `Trim()` 并原样返回，**不做存在性检查、不回退系统 Python**。路径写错/venv 被删时，`CreateProcess` 失败 → 故障原因进列表底部信息条与 `logs\service\` 日志，属可观测失败。
- **托盘图标取材**：`app.ico` 原先只作 `<ApplicationIcon>`（仅影响 exe/快捷方式），运行时 **取不到**；必须再加 `<Resource Include="Resources\app.ico" />` 才能经 `pack://application:,,,/Resources/app.ico` 读取（Build Action 默认 None 不进资源索引）。读取用 WPF 原生 `IconBitmapDecoder`（`BitmapImage` 不能可靠解码 .ico；**不要**为此引入 System.Drawing.Common）：`Application.GetResourceStream` → 取 `PixelWidth` 最大的帧 → 赋 `Tray.IconSource`。
- **必须保留矢量兜底**：XAML 里的 `TrayIconSource` 不删，`ApplyTrayIconFromAppIcon()` 整段 try/catch 静默失败。任何情况下托盘必须有图标，否则 `--minimized` 登录自启后用户再无入口。
- **与 `--minimized` 的次序**：`ApplyTrayIconFromAppIcon()` 放在 `Window_Loaded` 内、`Dispatcher.BeginInvoke(DispatcherPriority.Loaded, HideOnStartup)` **之前**即可；不要把它挪出 `Window_Loaded`（托盘图标在窗口内容 Loaded 时才创建）。
