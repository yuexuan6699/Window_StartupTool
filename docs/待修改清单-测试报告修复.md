### F5 · 补日志落盘实现（观察项 ①）

**新增文件**：`src/StartupTool.Core/Logging/LogStore.cs`

职责与规则：
- **服务日志**：`{基目录}\logs\service\service-yyyyMMdd.log`，写 `Fault` / `Information` 两类监管事件与启动期警告；不写 `StateChanged`（高频噪音）。
- **脚本日志**：`{基目录}\logs\scripts\<净化后脚本名>_<Id 前 8 位>\output-yyyyMMdd.log`，写脚本 stdout/stderr 每一行。
- **滚动**：单文件超过 `settings.LogMaxSizeMb` 时切分片（`service-yyyyMMdd-2.log`、`-3.log`…）。
- **清理**：超过 `settings.LogRetentionDays` 的文件在服务启动时清理一次（并每日复核一次）。
- 线程安全：内部加锁；任何 IO 异常一律吞掉（日志失败绝不影响守护）。

**接入**：
- `src/StartupTool.Service/SupervisionWorker.cs`：新建 `LogStore`，并把 `RelayEventSink` 扩展为「事件同时送 IpcServer 与 LogStore」（多目标转发）；启动期 `InitialLoadError`/`InitialSaveError`/`AclProtectionFailed` 三条警告改为"控制台照旧 + 同时落服务日志"。
- `ScriptSupervisor.BeginReadOutput()` 已为每行 `Emit(ScriptOutput)`，经 sink 组合后自然落盘，**无需改 Core 监管逻辑**。

**新增测试**：`tests/StartupTool.Core.Tests/LogStoreTests.cs`
- 写入后文件存在且内容含时间戳与消息；
- 超过 `LogMaxSizeMb` 触发分片；
- 超过 `LogRetentionDays` 的旧文件被清理；
- 脚本日志目录名符合 `<名>_<短哈希>`。

**文档**：`开发文档.md` 补日志模块与目录约定；`项目文档.md` 第 7 节"日志"处更新（原描述与实现不符）。

**连带收益**：B11 诊断包将真正包含 `logs/service/*`（`DiagnosticsPackager` 已实现取该目录，无需改动）。

### F8 · 外部改配置后控制端自动刷新（观察项 ④）

**文件**：`src/StartupTool.Core/Configuration/ConfigService.cs`、`src/StartupTool.Core/Ipc/IpcServer.cs`、`src/StartupTool.Core/Ipc/IpcMessage.cs`、`src/StartupTool.App/AppClientService.cs`

1. `ConfigService`：新增 `public event Action<AppConfig>? ExternallyChanged;`，**仅在 `ReloadFromDisk()` 成功（非本进程写入）时触发**；`Mutate()`（本进程写）不触发它 —— 避免每次界面增删改都重复广播。
2. `IpcServer`：构造后订阅 `_config.ExternallyChanged` →
   - `Enqueue(new StatesBroadcast())`（`GetStates()` 始终遍历全部配置脚本，新增/删除行都会正确同步）
   - `Enqueue(new ConfigBroadcast(_config.Current))`（新增 `ConfigBroadcast` 记录类型 + `DispatchBroadcastAsync` 分支，发 `IpcTypes.ConfigData`，载荷 `AppConfigPayload`）
   - 广播直接在订阅回调中 `Enqueue`，与现有 `ForwardingSink` 模式一致（只入队，不阻塞）。
3. `AppClientService.OnEvent`：新增 `case IpcTypes.ConfigData:` → 解析 `AppConfigPayload` → 触发既有 `ConfigReceived` 事件（`App.xaml.cs` 已有处理器：`SetConfig` + 应用语言 + `RefreshLocalization`）。

**新增测试**：在 `ConfigTransferTests` 或新类中补一条 —— 外部改写配置文件（`enableWatcher: true`）后，已连接客户端能收到 `configData` 帧与刷新后的 `scriptStates`。

**注意**：`Changed` 事件（本进程写）现有订阅者 `ScriptSupervisor` 保持不变。
