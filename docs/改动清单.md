## 〇、已确定的产品决策（不要再改）

| 编号 | 决策 | 结论 |
|---|---|---|
| P1 | 交互模型 | 同"远程软件"：服务端**开机即启**（Windows 服务，SYSTEM，无需登录），控制端**登录后自动启动**（WPF，托盘+主窗口），在桌面上操作 |
| P2 | 技术栈 | .NET 10 + **WPF** + MVVM；单 exe 双模式（`--service` / 无参） |
| P3 | 进程归属 | **服务端是唯一权威所有者**；控制端只通过命名管道下发命令、渲染状态，**自身绝不启动/杀死脚本进程** |
| P4 | 脚本运行会话 | 默认在**当前登录用户会话**内启动（保证界面可见）；无人登录时排队，登录后补启动；每脚本可切「在系统会话运行」 |
| P5 | 进程托管单位 | **Windows Job Object**（`KILL_ON_JOB_CLOSE`，不授予 BREAKAWAY） |
| P6 | 外部同名进程 | **只展示、不自动杀**（用户已明确：不做「严格托管」开关） |
| P7 | 明确不做 | Web UI（删掉 `RunMode`/`WebPort` 死字段）、云同步、自动更新、插件系统、脚本签名校验 |
| P8 | 文档 | 必须产出并持续维护 `项目文档.md` + `开发文档.md` |
| P9 | 应用层心跳 | 每脚本独立令牌；脚本调用 `StartupTool.exe --beat <令牌> <时间戳>`，经命名管道投递服务；超时判卡死→重启 Job；计入熔断。详见 H 类 |
