### 1.1 命令行模式（同一个 exe）

```powershell
StartupTool.exe                 # 无参 = WPF 控制端（需先有 --console 或服务在跑）
StartupTool.exe --console       # 免安装宿主：脚本在"当前登录会话"启动，便于调试
StartupTool.exe --service       # 服务模式（由 SCM 拉起，不要手敲）
StartupTool.exe --install       # 注册并启动服务（需管理员）
StartupTool.exe --uninstall     # 卸载服务（需管理员）
StartupTool.exe --beat <令牌> <Unix秒>   # 脚本上报心跳（一次性进程，不常驻）
```

### 1.2 退出码契约

| 场景 | 退出码 |
|---|---|
| `--beat` 成功 | 0 |
| `--beat` 参数错 / 令牌格式非法 | 10 |
| `--beat` 连不上服务 | 11 |
| `--beat` 令牌无效或已重置 | 12 |
| `--beat` 时间戳偏差 > 300 秒 | 13 |
| `--beat` 通信超时 / 协议错 | 14 |
| `--beat` 令牌有效但脚本当前**未运行** | 15 |
| `--install` 非管理员运行 | 5 |
| `--install` 发布目录里找不到 exe | 20 |
| `--install` 服务已注册但启动失败 | 21 |

### 1.3 配置字段（v2，`config\scripts.json`）

顶层：`version`(=2)、`settings`（全局）、`scripts[]`（按 `order` 依次启动）。

脚本字段（真实样例见现存 `bin\Debug\net10.0-windows\config\scripts.json`）：

```jsonc
{
  "id": "…32位hex，自动生成，勿手改…",
  "name": "显示名称", "path": "C:\\Windows\\System32\\notepad.exe", "arguments": "",
  "pythonExecutable": "",        // D10：仅 .py/.pyw；venv 的 Scripts\python.exe 完整路径，留空用系统 py.exe/python.exe
  "order": 1,
  "autoStart": true,            // 开机/服务启动时自动拉起
  "manualEnabled": true,       // 允许手动"启动"
  "runInSystemSession": false,  // true = 在 Session 0 跑（不落桌面）
  "workingDirectory": "", "environmentVariables": {},
  "requireElevation": false,    // D6：true = 以 SYSTEM 提权运行（仍落登录用户桌面）
  "initialDelaySeconds": 0, "waitForNetwork": false,        // D3：启动前延迟 / 等网络就绪
  "dependsOn": [], "startIntervalSeconds": 0,               // D4：依赖脚本 / 依次启动间隔
  "maxCpuPercent": 90, "maxMemoryMb": 0, "maxGpuPercent": 90,   // 0 = 不限
  "restartDelaySeconds": 10,
  "crashRestart": "OnFailure",  // Never / OnFailure / Always
  "maxRestartsPerWindow": 0,    // 0 = 用全局 circuitMaxStarts
  "heartbeatEnabled": false,
  "heartbeatIntervalSeconds": 30, "heartbeatTimeoutSeconds": 90, "heartbeatToken": ""
}
```

全局 `settings`：`logMaxSizeMb`(5)、`logRetentionDays`(30)、`circuitWindowSeconds`(60)、`circuitMaxStarts`(10)、`notifyOnFault`(true)、`language`(zh-CN)。（全部可在 WPF「设置 → 界面与日志」中修改；数值越界由服务端校验拒绝。）

> **手改 JSON 只用于测试准备**；改完必须在 WPF 里"刷新"或重启宿主才会热加载（服务端 250ms 防抖热重载，解析失败会**保留旧值**并在日志里告警）。
> **权限**：配置目录/文件会被自动收紧为仅 SYSTEM 与 Administrators；非提权调试环境收紧失败会在服务日志明确告警，不会假装已保护。

## 2. 判定约定

- **PASS**：完全符合"期望"；**FAIL**：与"期望"不符；**BLOCKED**：环境不满足（如无管理员/无 GPU/托盘图标不可点）；**N/A**：本次环境不适用。
- 每条用例都要留**证据**：截图 / 命令输出 / 日志片段 / `scripts.json` 片段（任选 1–2 项，能证明结论即可）。
- 出现 FAIL 时**先别急着改代码**，按第八节收集证据再回报。

### A 组 · 自动化回归（任意机器，无需 VM 桌面）

**A01 构建 0 警告 0 错误**

```powershell

Get-Process StartupTool,ping,notepad -ErrorAction SilentlyContinue | Stop-Process -Force
cd <源码根>\StartupTool.Rework
dotnet build StartupTool.slnx -c Debug   -v m
dotnet build StartupTool.slnx -c Release -v m
```
- 期望：两次都是 `已成功生成。/ 0 个警告 / 0 个错误`，退出码 0。
- 证据：把两次输出的末尾 3 行贴回。

**A02 全量测试 125 项通过**

```powershell
dotnet test StartupTool.slnx -c Debug
```
- 期望：`已通过! - 失败: 0，通过: 125，已跳过: 0，总计: 125`，退出码 0。
- 注意：测试会**真实创建并杀掉进程**，务必先执行 A01 的前置清理；测试已关闭并行，属正常设计，不要用超短超时。
- 已知抖动：`IpcEndToEndTests.心跳投递_成功_非法令牌_时钟偏差` 偶发返回 `ProtocolError`（心跳客户端连读写**总超时 3 秒**，并行负载下偶现；单独重跑即绿）。属测试环境抖动，**非缺陷**；若复现，先 `--filter "FullyQualifiedName~心跳投递"` 单独重跑确认。
- 失败处理：任何一条失败都视为 FAIL，把失败用例名与断言消息贴回。

**B01 自动启动与状态一致性**
- 步骤：启动 `--console` 后等宿主完成启动（有约 10 秒的"等系统就绪"窗口），观察脚本表格。
- 期望：`autoStart=true` 的脚本自动进入`运行中`，PID/会话/运行时长有值；`已连接守护服务`；关闭控制端再重开，状态自动恢复（事件推送，非轮询）。
- 证据：截图 + `logs\service\` 对应时间段日志。

**B02 启停与"全部停止"**
- 步骤：① 单行点`停止`→ 状态变`已停止`；② 点`启动`→ 重新运行且 **PID 与之前不同**；③ 点`重启`→ 旧进程消失、新进程出现；④ 托盘右键`全部停止` → 所有脚本停止。
- 期望：每次只有一个实例在跑（**不得出现同一脚本两份进程**），停止后子进程一并消失。
- 检查：任务管理器里该脚本进程数恒为 1。

**B03 实时输出窗（重点回归）**
- 步骤：① 点"测试脚本-ping"行的`输出`按钮；② 观察约 5 秒，再点工具栏`清空显示`；③ 再点同一行`输出`开出**第二个**输出窗；④ 两个窗分别点右上角关闭。
- 期望：① 窗标题`实时输出：测试脚本-ping`，每约 1 秒追加一行 `来自 127.0.0.1 的回复: …`；② 清空后列表为空、窗口不卡、随后继续出现新行；③ 两个窗同时存在且**互不干扰**；④ 关闭后主窗正常、进程未退出。
- 证据：截图（含时间戳行）。

**B04 编辑脚本保存生效 + 令牌不被覆盖**
- 步骤：① 右键"记事本"行 → `编辑脚本…`；② 把`崩溃后重启等待（秒）`改成 `30`，保存；③ 再打开同一脚本，确认值为 30；④ 先右键该行 → `心跳命令…` 复制令牌，回到编辑窗把`显示名称`改一个字保存，再开`心跳命令…`，比对令牌。
- 期望：① 修改立即持久化（`config\scripts.json` 中 `restartDelaySeconds`=30）；② **令牌不变**（编辑保存不得覆盖/清空服务端权威字段）。
- 证据：`scripts.json` 相关片段 + 前后令牌各一张截图（可只比对前 8 位）。

```powershell

New-Item -ItemType Directory -Force C:\startuptool-test | Out-Null
@'

Add-Content -Path $log -Value ("服务状态 = " + (Get-Service StartupTool).Status)

  /TR "powershell -NoProfile -ExecutionPolicy Bypass -File C:\startuptool-test\probe.ps1"
```

## 5. 明确**不需要**人工重复测的部分（已有自动化覆盖）

以下内容在 125 项测试中已有断言，人工不必重复；如要抽查只做"顺带观察"即可：

- Job Object 托管：终止整树、`cmd start` 接力、离群子进程兜底
- 每脚本状态机（Stopped/Starting/Running/Stopping/Faulted）与 `SemaphoreSlim` 串行化、并发启停/重启
- 崩溃自愈、熔断计数与恢复（D02/D03 只是人工复核观感）
- 心跳超时终止与 `NotRunning` 语义（E02 同上）
- 配置原子写 + `.bak`、解析失败保留旧值、v1→v2 迁移、Id 去重、令牌生成/重置/固定时间比较
- IPC：帧 1MB 上限、空闲超时回收、保活、会话过滤、广播并行、`startScript` 拒绝回 `rejected`
- 安装器命令构造（`sc` 参数、`reset= 86400`、提权探测）、退出码 5/20/21
- 进程匹配（外部同名进程只读扫描，不自动终止）、工作目录解析优先级
- 管道 ACL 的位标志组合（**无法用人工手段直观验证，属自动化域**）
- **D3/D4 启动时序**（`DeStartupFlowTests`：启动前延迟、等网络、依赖就绪/超时放弃、依赖成环与悬空引用清理、网络探测）
- **D7/D8**（`ConfigTransferTests`：导入/导出含 `requireElevation` 等字段保留；`DiagnosticsPackagerTests`：打包 zip、令牌打码）
- **D9 模板**（`ScriptTemplatesTests` ×7：心跳三模板预填开关、`MapNetworkDrive`/`WindowsService` 预填、模板查找与草稿）

## 6. 已知"非缺陷"，请勿判 FAIL

| 现象 | 解释 |
|---|---|
| 数字框输 `abc` 时红框出现但`保存`仍可点，且保存下去还是旧值 | WPF 固有行为：类型转换失败不写源。要彻底拦死需输入掩码/字符串型属性，属**已知剩余项**，不是回归 |
| 工具栏里找不到`上移`/`下移` | 这两项在**行右键菜单**里 |
| 无人登录时脚本不启动 | 设计如此：服务先起，脚本排队，登录后 5 秒内补发 |
| 外部同名进程窗里列出别的同名进程，但工具不会自动杀掉 | 既定策略：外部进程**只展示**，仅在你显式确认后才终止 |
| 点击`×`后"窗口不见了" | 设计如此：× = 最小化到托盘；用托盘`显示主窗口`恢复 |
| 被 Job 终止的脚本退出码不是 0 | 预期：终止属强制结束 |
| 服务日志里出现"ACL 收紧失败/未保护"警告（仅非提权调试环境） | 预期：非提权时如实告警，不假装已保护 |
| 非中文系统选"跟随系统"后，语言保存显示为中文 | 已知低风险瑕疵（`null` 经序列化往返变 `zh-CN`），本次不要求修，记 FAIL 亦可但请标注为"已知" |
| 行拖拽排序用合成鼠标事件拖不动 | 属测试手段限制（WPF 拖放对合成事件响应有限）；请**用真人鼠标**验证，或标 BLOCKED |
| 导入配置后脚本心跳令牌被清空 | 设计如此：令牌只能服务端生成（N3）。重新在 `心跳命令…` 取值即可 |
| `IpcEndToEndTests.心跳投递…` 偶发 `ProtocolError` | 心跳客户端连读写**总超时 3 秒**，并行负载下偶现；单独重跑即绿，属测试环境抖动，非缺陷 |

## 7. 失败时的证据收集

1. **服务/守护日志**：`{exe 目录}\logs\service\`（含启动期加载/保存警告、ACL 警告、心跳与重启记录、D6 提权/依赖/延迟记录）。
2. **脚本输出**：`{exe 目录}\logs\scripts\<脚本名_短哈希>\`。
3. **配置快照**：`{exe 目录}\config\scripts.json` 与 `scripts.json.bak`（注意内含令牌，回报时**打码**）。
4. **事件日志**：事件查看器 → `Windows 日志/系统`（来源 `Service Control Manager`），特别是 D01/C01/D02。
5. **进程事实**：`Get-Process … | Select Id,ProcessName,SessionId,StartTime,Path`。
6. **界面**：截图（含窗口标题、状态列、气泡通知）。
