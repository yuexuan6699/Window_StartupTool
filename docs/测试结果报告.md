### 3.8 观察项（B 组过程中确认）

- `logs\service\` 与 `logs\scripts\` 目录**创建但为空**：VM 内长时间运行后两目录仍无任何文件。源码侧 `AppPaths` 只 `CreateDirectory`，未见文件日志写入实现（`settings` 中 `logMaxSizeMb` / `logRetentionDays` 有校验但无落盘路径）。
  → 影响：B01「logs 对应时间段日志」、B11「诊断包内含服务日志」两项**无文件证据可采**，已按实际表现记录（B11 实测 zip 内确无 `logs/service/*` 条目）。
- **设置窗无数值输入项，与《测试交接文档》§1.3 描述不一致**：本构建的 `Views/SettingsWindow.xaml`（共 44 行）只有 3 个语言 `RadioButton` + 1 个通知 `CheckBox` + `关闭` 按钮，**没有任何数值输入控件**。
  → 全局数值项（`logMaxSizeMb`、`logRetentionDays`、`circuitWindowSeconds`、`circuitMaxStarts`）在 UI 上**无入口可改**；文档 B08 步骤②（把熔断窗口填成 `0`）**无法执行，判 N/A**。该数值范围校验的 UI 入口实际在**脚本编辑窗**（B05，受 B04 阻塞）。
- **诊断包文件名与文档不符**：文档要求 `startuptool-diagnostics-<时间戳>.zip`，实测为 `diag-<yyyyMMdd-HHmmss>.zip`（`DiagnosticsPackager.cs` 28 行即此命名）。内容条目本身齐全。
- **行内按钮启用态与状态栏的一致性（UIA 实测）**：收尾还原基线并重启宿主/控制端后，界面为 `3/3 个脚本运行中`，3 行的按钮启用态实测为 `启动=False / 停止=True / 重启=True / 输出=True`，与「全部运行中」自洽。
  ⚠ 方法学提醒：截图中按钮文字的**颜色深浅不足以判断启用态**（本构建的按钮样式对禁用项仍用主题色渲染），必须先取得 UIA `IsEnabled` 才可下结论——本节此前依据截图对单行按钮态的描述已按此实测口径修正。
- **外部直接改写 `config\scripts.json` 后，控制端列表未自动刷新（实测）**：收尾时把基线配置写回磁盘，控制端在随后 ≥25 秒观察窗内仍显示旧行数（4 行 / `2/4 个脚本运行中`），直到**重启控制端**才显示为 3 行 / `3/3 个脚本运行中`。守护宿主侧确实注册了 `FileSystemWatcher`（`ConfigService.cs` 90-101 行：`LastWrite|Size|FileName` + 去抖定时器 → `ReloadFromDisk`），但**本次未能直接取证服务端内存是否已重载**（`beat-demo` 在还原前已因熔断而不存在，不能作为判据）。故仅记录「控制端不跟随服务端配置变更刷新列表」这一可复现现象，服务端重载行为建议开发侧加断言确认（本次未改代码）。
