# Window_StartupTool 重做版 · 项目文档

> 面向使用者。架构与协议细节见《开发文档.md》；所有改动登记于《改动清单.md》。
> 本文档随代码同步更新（每改一次代码必更）。

## 1. 这是什么

一个 Windows 开机启动项守护工具：在系统开机（**无需登录**）时由 Windows 服务拉起脚本，并在登录桌面后提供图形控制端进行管理。交互模型类似远程控制软件——**后台服务开机即运行，进入桌面后可以控制**。

相比旧版，重做版解决三类问题：

1. **架构重做**：旧版脚本在 Session 0 启动，带界面的程序看不到；新版默认在登录用户的桌面会话启动。
2. **修 Bug**：重启竞态（重复实例/误杀新进程）、句柄泄漏、GPU 恒为 0、配置热重载清空、服务安装路径引号等 20 项。
3. **修交互**：补上编辑、拖拽排序、弹窗表单、增量刷新、托盘摘要、异常通知、运行状况可视化等。

## 2. 组成

| 组件 | 身份 | 何时运行 | 职责 |
|---|---|---|---|
| Windows 服务（同一 exe，`--service`） | SYSTEM | 开机即启，无需登录 | **唯一权威所有者**：配置、调度、进程托管、崩溃自愈、资源监控、心跳判定、日志、IPC 服务端 |
| WPF 控制端（同一 exe，无参） | 登录用户 | 用户登录后自启；托盘常驻 | 只通过命名管道下发命令、展示状态；**自身绝不启停脚本进程** |

发布产物只有一个 `StartupTool.exe`，通过启动参数切换身份：

| 启动方式 | 用途 |
|---|---|
| 无参 | WPF 控制端（每会话单例，重复启动会唤起已有窗口） |
| `--service` | Windows 服务模式（SCM 调用，勿手工运行） |
| `--console` | 控制台调试模式：不安装服务也能跑完整宿主，脚本在当前会话启动 |
| `--install` / `--uninstall` | 注册 / 移除 Windows 服务（一般由 install.ps1 调用） |
| `--beat <令牌> <时间戳>` | 脚本心跳一次性投递，见第 5 节 |

## 2.1 守护行为（M3 已上线的核心能力）

- **整组托管**：脚本及其所有子孙进程放进同一个 Windows Job Object。脚本自己用 `start` 拉起接力进程后根进程退出，状态仍显示"运行中"；点"停止"一次清光整棵进程树，无残留。
- **崩溃自愈**：按脚本策略（不重启 / 仅失败时 / 总是）自动重启；重启走"停到位 → 确认进程组归零 → 延时 → 新组"流程，并发操作也不会出现两个实例。
- **熔断保护**：默认 60 秒内启动超过 10 次（可配）即进入"已熔断"，暂停自动守护并告警，防止死循环脚本疯狂产进程；可手动"恢复守护"。
- **外部同名进程**：手动双击启动的同名程序**只计数展示，绝不会被自动终止**；仅在界面显式确认后才终止。
- **资源守护**：CPU / 内存 / GPU 超限时自动重启；GPU 数据取不到时显示 N/A 而不是 0。
- **登录会话感知**：开机后无人登录时，脚本先排队（不消耗重启次数、不熔断）；用户一登录，5 秒内自动补启到该用户桌面；「在系统会话运行」的脚本不受影响，直接在 Session 0 启动。
- **应用层心跳**：见第 5 节。

## 3. 安装与卸载

> 需管理员权限。脚本位于仓库的 `tests\` 目录。

### 3.1 安装

在**管理员 PowerShell** 中执行：

```powershell
cd StartupTool.Rework
.\tests\install.ps1
```

脚本会：

1. 自检管理员权限（非管理员退出码 5）；
2. `dotnet publish` 发布 **self-contained 单文件**版（win-x64，目标机无需安装 .NET）到 `publish\`；
3. 调用 `publish\StartupTool.exe --install`（程序内部也会再自检一次管理员权限）：
   - 注册 Windows 服务 `StartupTool`（自动启动、LocalSystem），binPath 已正确处理带空格的安装路径（内层引号）；
   - 配置服务崩溃自动重启（5s / 10s / 30s），失败计数 24 小时无新失败自动清零；
   - 在 `HKLM\...\CurrentVersion\Run` 写入控制端登录自启项；
   - 立即启动服务。

每一步都检查退出码，任一步失败立即中止，不会"发布失败还继续装"。程序安装退出码：**5**=未以管理员身份运行、**20**=找不到可执行文件、**21**=服务已注册但启动失败（需查看服务日志）；描述/自启项等非关键步骤失败只给警告并在结尾汇总，不影响服务本体注册结果。

### 3.2 卸载

```powershell
.\tests\uninstall.ps1
```

停止并删除服务（容忍"服务不存在/已标记删除"），清除控制端登录自启项。发布目录 `publish\` 与 `config\`、`logs\` 不会被删除，需要时手工删除。

### 3.3 免安装调试

开发/排查时可不装服务：`StartupTool.exe --console`，宿主在当前控制台运行，脚本直接在当前用户会话启动，命名管道与控制端/心跳全部可用；关闭窗口或 Ctrl+C 即退出，退出时停止全部脚本（进程被强杀时 Job 也会兜底清光整棵进程树）。

## 4. 使用说明

> 需要后台守护服务（Windows 服务或 `--console`）已在运行；控制端只是操作面板，自身不启动/杀死脚本。

- **主窗口**：脚本列表实时显示状态（运行中/启动中/停止中/已停止/已熔断，五种颜色状态点）、PID、本次运行时长、重启次数、CPU/内存、外部同名进程数；顶部显示 `n/m 个脚本运行中`。
- **脚本管理**：「添加脚本」弹窗录入；双击行或行右键「编辑脚本…」修改；支持搜索过滤、上移/下移与拖拽排序（顺序即时保存）。行右键还提供：查看实时输出、心跳命令、外部同名进程、打开文件位置、恢复守护（仅熔断行出现）、删除。`.bat/.cmd/.ps1/.py/.pyw` 会按扩展名自动选用解释器（cmd / PowerShell / Python），无需在参数里写解释器；Python 脚本可用【Python 解释器】指定虚拟环境的 `Scripts\python.exe`（见 8.2）。
- **保存生效方式**：守护属性（资源上限、心跳、重启策略等）保存后立即生效；路径、参数等启动类属性在脚本运行中保存时会询问【立即重启】/【稍后手动重启】，停止状态下保存不询问。
- **实时输出**：行菜单「查看实时输出」打开，最多保留最近 5000 行、自动滚动到底部、可清空；脚本 stdout/stderr 同时落盘到 `logs\scripts\<脚本名_短哈希>\`。
- **熔断与恢复**：脚本在短时间内反复启动失败（如文件不存在、死循环自重启）会自动熔断并暂停守护（红点 + 红三角），故障原因显示在列表底部信息条；排除问题后在行菜单点「恢复守护」即可。
- **外部同名进程**：工具只识别和展示不是由它托管的同名进程，**不会自动终止**；在「外部同名进程」窗选中并点「终止选中进程」，二次确认后才执行。
- **托盘**：关闭（×）主窗口只是最小化到托盘，脚本守护不受影响，首次会提示并可勾选「不再提醒」；托盘左键恢复窗口，右键提供「显示 / 全部停止 / 脚本子菜单单击启停 / 退出控制端」。**「退出控制端」只关闭面板，不影响后台守护服务，脚本继续运行**；脚本故障/重启会弹托盘气泡，可在设置中关闭（关闭后列表状态照常更新）。
- **设置**：界面语言（跟随系统 / 中文 / English，实时切换无需重启）、故障气泡开关，以及「界面与日志」的 4 个全局数值项（单个日志文件上限 1–1024 MB、日志保留天数 1–3650、熔断统计窗口 1–86400 秒、窗口内最大启动次数 1–1000）；数值越界会被拒绝并在窗内显示原因，原配置保持不变。心跳令牌在每行的「心跳命令…」窗复制或重置（重置需二次确认）。
- 顶部另有「打开配置文件」「打开日志目录」按钮。

## 5. 脚本心跳接入（应用层心跳）

用途：发现"**进程没死但业务已经卡死**"。默认关闭，按脚本开启。

### 5.1 发送方式

脚本在每轮工作完成后，调用同一个 exe：

```
StartupTool.exe --beat <令牌> <时间戳>
```

- **令牌**：每个脚本一个，由服务端生成（界面可复制命令、可重置令牌）。
- **时间戳**：Unix 秒；与服务端时间偏差超过 300 秒会被拒绝（防重放/时钟异常）。
- 服务端只认令牌反查脚本；**是否存活以服务端收到包的时刻为准**。
- 发送失败时退出码非 0，控制台打印中文原因。退出码表：

| 退出码 | 含义 |
|---|---|
| 0 | 投递成功（成功不打印任何内容，避免脚本循环刷屏） |
| 10 | 参数错误（令牌不是 64 位十六进制、时间戳不是数字等） |
| 11 | 无法连接服务（服务未运行或管道不可用） |
| 12 | 令牌无效或已被重置（到控制端重新复制心跳命令） |
| 13 | 时间戳偏差超过 300 秒（校准系统时间） |
| 14 | 通信超时或协议错误 |
| 15 | 令牌有效但脚本当前未运行（已被停止、熔断或尚未启动；脚本内定时心跳收到此码应停止发送或告警，说明守护端已不再托管本脚本） |

### 5.2 超时行为

- 建议间隔默认 30 秒，超时默认 90 秒（均可按脚本配置）；启动后有 2 倍超时的宽限期。
- 超时未收到包 → 判定卡死 → 终止整个进程组（Job）→ 自动重启 → 告警 + 托盘通知。
- 反复超时重启会触发熔断（进"已熔断"，暂停自动守护，需手动恢复）。

### 5.3 脚本示例

> 以下均与重做版内置模板库（D9）的心跳示例同源，可直接复制；完整说明见《开发文档.md §5.3》。
> 使用前把两处改为你的实际值：`StartupTool.exe` 完整路径、控制端「心跳」窗口复制的 64 位十六进制令牌。
> 判据以**退出码**为准：`0` 表示服务端已确认收到；非 `0` 表示投递失败，应打印告警并**停止发送**。

**bat**（模板 `HeartbeatBat`）

```bat
@echo off
setlocal
set "BEAT_PATH=C:\path\to\StartupTool.exe"
set "TOKEN=REPLACE_WITH_YOUR_64_HEX_TOKEN"
set "INTERVAL_SECONDS=30"
:loop
    for /f %%t in ('powershell -NoProfile -Command "[DateTimeOffset]::UtcNow.ToUnixTimeSeconds()"') do set "TS=%%t"
    "%BEAT_PATH%" --beat "%TOKEN%" "%TS%"
    if errorlevel 1 (
        echo [心跳] 发送失败，退出码 %errorlevel%，停止发送。
        goto :eof
    )
    ping -n %INTERVAL_SECONDS% 127.0.0.1 >nul 2>&1
goto loop
```

**PowerShell**（模板 `HeartbeatPowerShell`）

```powershell
$BeatPath = "C:\path\to\StartupTool.exe"
$Token    = "REPLACE_WITH_YOUR_64_HEX_TOKEN"
$Interval = 30
while ($true) {
    $ts = [DateTimeOffset]::UtcNow.ToUnixTimeSeconds()
    & $BeatPath --beat $Token $ts
    $code = $LASTEXITCODE
    if ($code -ne 0) {
        Write-Host "[心跳] 发送失败，退出码: $code，停止发送。" ; break
    }
    Start-Sleep -Seconds $Interval
}
```

**Python**（模板 `HeartbeatPython`）

```python
import subprocess, time
BEAT_PATH = r"C:\path\to\StartupTool.exe"
TOKEN = "REPLACE_WITH_YOUR_64_HEX_TOKEN"
INTERVAL = 30
while True:
    proc = subprocess.run([BEAT_PATH, "--beat", TOKEN, str(int(time.time()))],
                          capture_output=True, text=True)
    if proc.returncode != 0:
        print(f"[心跳] 发送失败，退出码: {proc.returncode}，停止发送。")
        break
    time.sleep(INTERVAL)
```

## 6. 配置文件

路径：`{exe目录}\config\scripts.json`（v2 格式；旧版 v1 配置会被自动迁移，`RunMode/WebPort` 死字段被丢弃）。
**权限**：配置目录与 `scripts.json` 均收紧为仅 SYSTEM 与 Administrators 可访问（目录权限可继承，目录内新建的临时文件/备份同样受限，内含每脚本心跳令牌）。普通操作请用界面，不要手改；写入为原子替换并保留 `scripts.json.bak`；解析失败时**不会**清空运行中的配置。非提权调试环境若无法收紧权限，服务日志会明确给出警告（不会假装已保护）。

v2 顶层：`version`（=2）、`settings`（全局）、`scripts[]`（脚本数组，按 `order` 启动）。每个脚本字段：

| 字段 | 含义 | 默认 |
|---|---|---|
| id | 唯一标识（自动生成，勿改） | 自动 |
| name / path / arguments | 名称 / 脚本路径 / 参数 | — |
| pythonExecutable | **仅 .py/.pyw**：Python 解释器完整路径（通常指虚拟环境的 `Scripts\python.exe`）；为空回退系统 `py.exe`/`python.exe` | 空 |
| order | 启动顺序 | 自动排列 |
| autoStart / manualEnabled | 开机自启 / 允许手动启动（旧版 enabled 已拆分） | true / true |
| runInSystemSession | 在系统会话（Session 0）运行，否则在登录用户桌面运行 | false |
| workingDirectory / environmentVariables | 工作目录 / 自定义环境变量 | 脚本目录 / 空 |
| requireElevation | 提权运行 | false |
| initialDelaySeconds / waitForNetwork | 启动前延迟 / 等待网络（M6 生效） | 0 / false |
| dependsOn / startIntervalSeconds | 依赖脚本 id 列表 / 启动间隔（M6 生效） | 空 / 0 |
| maxCpuPercent / maxMemoryMb / maxGpuPercent | 资源上限，超限重启；0 表示不限 | 90 / 0 / 90 |
| restartDelaySeconds | 重启前等待秒数 | 10 |
| crashRestart | 崩溃策略：never/onFailure/always | onFailure |
| maxRestartsPerWindow | 熔断阈值（0=用全局默认） | 0 |
| heartbeatEnabled / heartbeatIntervalSeconds / heartbeatTimeoutSeconds / heartbeatToken | 心跳开关 / 建议间隔 / 超时 / 令牌 | false / 30 / 90 / 空 |

全局 `settings`：`logMaxSizeMb`(5)、`logRetentionDays`(30)、`circuitWindowSeconds`(60)、`circuitMaxStarts`(10)、`notifyOnFault`(true)、`language`(zh-CN)。

> **经界面/管道保存时的服务端保护**：① 心跳令牌只能由服务端生成（「心跳命令」窗的获取/重置），界面提交的脚本配置不会覆盖或伪造令牌；编辑脚本只更新可编辑字段，令牌、依赖等未暴露字段保持不变。② 全局设置有合法范围校验（熔断窗口 1–86400 秒、阈值 1–1000、日志上限 1–1024MB、保留 1–3650 天、语言仅限支持项），非法值会被拒绝并保留原配置。

## 7. 日志

- **服务日志**：`logs\service\service-yyyyMMdd.log` —— 守护故障（崩溃/资源超限/心跳超时/熔断/启动失败）、排队与登录补发等信息，以及配置加载/权限收紧的启动期警告。
- **脚本日志**：`logs\scripts\<脚本名_短哈希>\output-yyyyMMdd.log` —— 逐行记录脚本 stdout/stderr（与界面「实时输出」同源）。
- 当天文件超过上限时自动分片（`…-2.log`、`…-3.log`）；默认单文件 5 MB、保留 30 天，可在「设置 → 界面与日志」中调整。
- 顶部「打开日志目录」按钮可直达 `logs\`；导出的诊断包（D8）会一并打包最近的 `logs\service\` 日志。

## 8. FAQ / 故障排除

### 8.1 怎么添加一个 Python 脚本？

1. 准备好 `.py` 文件（例如 `D:\scripts\job.py`）。
2. 顶部「添加」→ 填【显示名称】→ 点【浏览…】选中该 `.py` 文件。
3. 其余按需设置（参数、工作目录、开机自启、崩溃重启等）→【保存】→ 在行内点【启动】。

`.py` / `.pyw` 由程序自动经 Python 解释器执行，**不需要**你自己写 `python xxx.py` 这类启动命令；
脚本参数也不要填 `python` 或脚本路径本身，只填传给脚本的参数（如 `--port 8080`）。

也可以用「从模板新建」：选模板后复制右侧脚本文本 → 自行保存为 `.py` 文件 → 回到编辑窗把该文件路径填进【脚本/程序路径】。
模板只提供文本，不会自动写盘。

### 8.2 怎么让脚本使用它所在文件夹的虚拟环境？

**不需要激活虚拟环境**。虚拟环境（`.venv`、`venv`、`env` 或任意自定义名字）只需在脚本编辑窗的
【Python 解释器】里选中该环境的 `Scripts\python.exe`，程序会直接用它执行脚本，依赖就是该环境里装的那些。

- 虚拟环境目录名不固定也没关系：该字段就是完整文件路径，与目录名字无关。
- 留空 = 使用系统 `py.exe`（找不到再退到 `python.exe`）。
- 该字段对非 Python 脚本无效，可放心留着。
- 若指定路径被删除或写错，脚本会启动失败，故障原因显示在列表底部的信息条与 `logs\service\` 日志中（不会静默改用系统 Python，避免"以为用了虚拟环境、实际用了全局环境"）。

### 8.3 脚本一直"启动中 / 启动失败"怎么排查？

按顺序看：① 列表底部信息条的故障原因；② 行菜单「查看实时输出」；③ `logs\service\service-yyyyMMdd.log`。
最常见原因：脚本路径不存在、缺少解释器（如未装 Python）、勾选「在服务会话（Session 0）中运行」但脚本需要交互桌面、开启了心跳却脚本内没发心跳（90 秒后被判超时重启）。
详见 [5.2 超时行为](#52-超时行为)。
